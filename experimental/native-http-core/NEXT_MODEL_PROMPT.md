## 目标和约束

- 现有 Lua key-auth、local limit-count、Prometheus 插件及其辅助源码不修改；插件业务继续在 Lua 中执行。
- 本次使用 standalone HTTP。Prometheus 全局启用；认证和限流只在指定前缀路由启用；对照基础、认证、限流、组合四个场景。
- 本次场景用到的路由、上下文、阶段调度、配置/身份合并、SDK、上游和清理等底层机制由 C 负责，不能依赖旧 APISIX Lua 核心完成业务。
- 健康检查、慢启动、服务发现、TLS/stream、所有插件兼容等不用扩展实现；只需既定场景正确和扩展骨架清楚。
- 保留 Lua table ABI、nil/false、getter/cache 时机、yield、执行顺序、共享配额、重试/keepalive、错误和配置代际语义。
- 可保留必要的薄 Lua 协程传输与 C 已发布缓存值的回放，核心决策不能迁回 Lua。
- 每个压力样本 60 秒、预热 5 秒，使用同硬件/依赖/配置的原版 Lua 作对照，报告 QPS、CPU/请求、p99、RSS 和错误。

## 已经尝试过什么

初始完整 C 实现曾比原版慢约 29%–40%，此前各轮负收益数据均保留。根据剖析，已逐步实施：

1. 去掉 Lua 桥接 pack 临时表，直接传输完整 varargs；缓存模块查找。
2. 按配置代际/消费者组合缓存合并配置与插件计划，保留共享对象身份与有界缓存。
3. `upstream_response_time` 等直接调用既有运行时导出的 typed C API；普通变量用 NGINX API。
4. 标量 header、变量写入、上游 peer/timeout/retry/keepalive 直接调用 C API，去掉 Lua/FFI 中转。
5. 合并 C 阶段完成/取下一回调/退出转换；按代际缓存上下文元数据；预分配表容量。
6. 对无 Lua filter 回调、脚本和 tracing 的配置使用纯 C header/body filters，并保留通用回调路径及失败关闭守卫。
7. 固定窗口整数形状的限流诊断 JSON 用 C 编码，Lua 字符串延后创建；其他形状保留通用路径。
8. C 批量准备日志/指标变量，保留已缓存值（含 false）与自定义 getter 的执行时机；Lua 只回放 C 已发布缓存。
9. 二进制原子替换，防止旧 worker 的 mmap inode 被覆盖；测量拒绝 sanitizer/剖析二进制，报告校验源码哈希。

用过 LuaJIT 状态采样、独立 PC 采样和 GCC 函数调用剖析。PC 采样无完整调用栈；GCC 子树时间包含 instrumentation 开销，不能当全 worker CPU 占比或验收吞吐。
当前不能把每一项总收益拆成独立贡献，也不能把不同轮次绝对 QPS 的差异直接归因于某个修改。
